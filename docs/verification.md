# 계산 결과 검증

앱이 계산한 계정 금액과 재무비율을 **OpenDART의 다른 API**와 대조하고, 차이가 나면 원인을 기록합니다.

- 실행: `python -m scripts.verify_reports` (기본: 삼성전자·SK하이닉스·현대자동차, 2025 사업보고서)
- 자동 생성된 전체 표:
  - [verification_result.md](verification_result.md): 2025 사업보고서
  - [verification_result_2026H1.md](verification_result_2026H1.md): 2026 반기보고서
- 검증일: 2026-10-18

## 1. 무엇과 비교했나

| 검증 대상 | 앱이 쓰는 데이터 | 비교 기준 (독립된 출처) |
|---|---|---|
| ① 계정 금액 | 전체 재무제표 API `fnlttSinglAcntAll` + 앱의 계정 매칭 규칙 | 주요계정 API `fnlttSinglAcnt` (회사가 공시한 주요 계정 요약) |
| ② 재무비율 | 앱의 `calculations.py` | 주요 재무지표 API `fnlttSinglIndx` (**금융감독원이 계산해 제공하는 지표**) |

①에서는 계정 매칭, 금액 변환, 당기/전기 필드 선택을 확인하고, ②에서는 공식, 평균 잔액, 연결 기준 처리를 확인합니다.
DART 지표가 없는 비율은 **사업보고서 수치로 직접 손계산**해 확인했습니다(4장).

## 3. 차이와 원인

### 3-1. ROE: 연결 기준의 분자·분모가 다름

| | 앱 | DART 지표 |
|---|---|---|
| 분자 | **지배기업 소유주 귀속** 당기순이익 | 당기순이익 (비지배지분 포함 전체) |
| 분모 | 평균 **지배기업 소유주지분** | 평균 자본총계 |
| 삼성전자 2025 | 10.848% | 10.783% |

- **확인 방법**: 검증 스크립트가 앱 데이터로 'ROE-전체기준'(당기순이익 ÷ 평균 자본총계)을 따로 계산합니다. 세 회사 모두 DART 값과 소수 셋째 자리까지 **일치**해서 원인이 확정됐습니다.
- **앱 기준을 유지하는 이유**
  - 요구사항("연결 기준 ROE는 지배기업 소유주 귀속 순이익 / 지배기업 소유주지분")을 따른 것입니다.
  - 주주 입장의 수익률을 보려면 비지배지분을 제외하는 것이 맞습니다. 증권사 리포트의 ROE도 보통 이 기준입니다.
- SK하이닉스는 비지배지분이 매우 작아 두 기준의 차이가 0.007%p에 그쳤습니다.

### 3-2. 분기·반기의 ROE·회전율: 앱은 연환산, DART는 연환산하지 않음

| 삼성전자 2026 반기 | 앱 (연환산 ×12/6) | 앱 ÷ 2 | DART 지표 |
|---|---|---|---|
| 총자산회전율 | 0.921회 | 0.460회 | 0.460회 ✓ |
| 재고자산회전율 | 9.849회 | 4.924회 | 4.924회 ✓ |
| ROE | 47.857% | 23.93% | 23.404% |

- 회전율은 연환산을 빼면 정확히 일치합니다.
- ROE는 연환산 차이와 3-1의 지배기업 기준 차이가 **함께** 있습니다. 실제로 'ROE-전체기준'(연환산 없음) = 23.404%로 DART와 일치합니다.
- **앱 기준을 유지하는 이유**: 반기 순이익을 그대로 쓰면 ROE가 연간 수치의 약 절반으로 나와, 사업보고서 ROE나 다른 회사의 연간 ROE와 비교할 수 없습니다. 기획 단계에서 사용자와 정한 기준이며, 화면에 '연환산(×12/6)'을 표시합니다.

### 3-3. (검증 스크립트 쪽 문제) 분기 손익 금액이 처음엔 '불일치'로 나옴

- 처음 실행했을 때 반기 매출액·영업이익·순이익이 6건 불일치로 나왔습니다.
  - 예: 삼성전자 순이익 — 앱 118.8조 vs 주요계정 API 71.6조
- 원인: 주요계정 API도 분기 손익의 `thstrm_amount`는 **3개월치**이고, 누적은 `thstrm_add_amount`에 있습니다. 앱은 누적값을 쓰는데 스크립트가 3개월치와 비교하고 있었습니다.
- 해결: 누적은 누적끼리, 3개월은 3개월끼리 비교하도록 스크립트를 고쳤고, 모두 일치했습니다.
- → 앱이 요구사항 6번(분기 3개월/누적 구분)을 올바르게 처리하고 있음을 **양쪽 값으로** 확인한 셈입니다.

## 4. DART 지표가 없는 비율: 손계산 대조 (삼성전자 2025, 연결)

DART가 제공하지 않는(또는 값이 비어 있는) 비율은 공시 원문 재무제표 숫자로 직접 계산했습니다. 단위는 조원입니다.

| 비율 | 손계산 | 결과 | 앱 |
|---|---|---|---|
| 당좌비율 | (247.68 − 52.64) ÷ 106.41 | 183.3% | 183.30% ✓ |
| 매출액영업이익률 | 43.60 ÷ 333.61 | 13.07% | 13.07% ✓ |
| ROA | 45.21 ÷ ((514.53 + 566.94) ÷ 2) | 8.36% | 8.36% ✓ |
| 매출채권회전율 | 333.61 ÷ ((43.62 + 51.13) ÷ 2) | 7.04회 | 7.04회 ✓ |
| 이자보상배율 | 43.60 ÷ 0.4697 (이자의 지급) | 92.8배 | 92.82배 ✓ |
| 영업현금흐름/순이익 | 85.32 ÷ 45.21 | 1.89배 | 1.89배 ✓ |

- **이자보상배율 참고**: DART 지표에서도 삼성전자의 이자보상배율은 **값이 비어 있습니다**. 손익계산서에 이자비용이 별도로 없기 때문으로 보이며, 앱이 '이자의 지급'(현금기준)을 대용치로 쓰기로 한 판단을 뒷받침합니다.
  - 대용치는 현금 기준이라 발생 기준 이자비용과 다를 수 있습니다. 정확한 값은 사업보고서 주석의 이자비용으로 확인해야 합니다.

## 5. 검증의 한계

- 대조 기업이 대형 제조업 3곳뿐입니다.
  - 계정 매칭이 까다로운 소형사는 `scripts/check_matching.py --random 25`로 '계정이 잡히는지'만 점검했고, 금액 대조는 하지 않았습니다.
- 주요계정 API와 전체 재무제표 API는 같은 공시에서 나온 데이터라서, **회사가 공시한 숫자 자체의 오류**는 잡아낼 수 없습니다.
- 금융업은 일반 비율이 부적합해 검증 대상에서 뺐습니다.
