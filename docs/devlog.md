### 내린 결정과 이유
- **라이브러리 버전 고정(`==`)**: 나중에 Streamlit Cloud에 배포할 때도 내 PC와 같은 버전이 설치되도록 했습니다.
- **`.env.example` 커밋**: 실제 키가 든 `.env`는 올리지 않고, 어떤 변수가 필요한지만 알려주는 예시 파일을 올립니다.

### 겪은 문제와 해결
- **Python이 설치되어 있지 않았음** → python.org에서 설치했습니다.
  - Windows의 "앱 실행 별칭"이 `python` 명령을 Microsoft Store로 연결하고 있어서, 설치 안내에 이 기능을 끄는 방법을 넣었습니다.
- **설치된 버전이 3.15(막 출시된 최신판)였음**
  - 새 버전이 나온 직후에는 pandas 등의 설치 파일(wheel)이 아직 없는 경우가 있어서, 설치 전에 `pip install --dry-run --only-binary :all:`로 확인했습니다.
  - 모든 라이브러리가 3.15를 지원해서 그대로 사용하기로 했습니다.
  - 배포 시 Streamlit Cloud에서 3.15를 고를 수 없으면 3.13을 선택할 예정입니다. 코드는 특정 버전 기능에 의존하지 않게 작성합니다.

### 겪은 문제와 해결

  - corpCode.xml에는 상장폐지 기업도 옛 종목코드를 가진 채 남아 있어, 이름이 같은 회사가 30쌍 있었습니다.

  - 해결 1: 이름이 같으면 최근 변경일(modify_date)이 늦은 쪽을 먼저 보여주도록 했습니다.

### 내린 결정과 이유
- **먼저 실제 응답을 보고 설계함**: 삼성전자 사업보고서·반기·1분기 응답을 직접 열어 필드 구조를 확인했습니다.

  | 구분 | 사업보고서 | 분기·반기보고서 |
  |---|---|---|
  | 재무상태표 | 당기말 / 전기말 | 분기말 / **전기말(=기초)** |
  | 손익(IS·CIS) | 당기 / 전기 | `thstrm_amount`=**3개월**, `thstrm_add_amount`=**누적**, `frmtrm_add_amount`=전년 같은 기간 누적 |
  | 현금흐름 | 당기 / 전기 | `thstrm_amount`가 **이미 누적**, 비교는 `frmtrm_q_amount` |

  → 분기 손익은 누적값을 쓰고 3개월값은 참고용으로 따로 보관합니다. 현금흐름표는 필드 이름이 손익과 달라서 별도로 처리했습니다.
- **한 기간 = 보고서 1건**: 각 연도 보고서의 '당기'와 '전기'만 사용합니다.
  - 기초 잔액(전기말)과 성장률 비교값(전기)이 같은 보고서 안에 있어 계산이 단순해집니다.
  - 비교값은 재작성(restated)된 수치를 쓰게 되어 회계적으로도 맞습니다.
  - 5개년 추이는 회사당 5번 호출하며, 캐시 덕분에 두 번째부터는 호출이 없습니다.
- **캐시 정책**
  - 정상 응답은 영구 보관합니다.
  - '데이터 없음'은 1일만 보관합니다. 아직 제출되지 않은 보고서가 나중에 생길 수 있어서입니다.
  - 정정공시 반영이 필요하면 `.cache/fs/`를 지우면 됩니다.
- **이자보상배율의 이자비용 대용치**
  - 점검 결과, 대표 기업 7곳(삼성전자, 현대자동차 등)과 무작위 표본 대부분이 손익계산서에 '이자비용'을 따로 표시하지 않고 '금융비용'으로 묶어 보고했습니다. 금융비용에는 외환손실·파생상품손실이 섞여 있어 그대로 쓰면 왜곡됩니다.
  - 그래서 손익계산서의 이자비용이 없으면 현금흐름표의 **'이자의 지급'(현금 기준)**을 대용치로 쓰고 화면에 표시합니다. 이자비용은 주석에만 나오는데, 이 API는 주석을 제공하지 않습니다.
- **금융업 판별**
  - 업종코드 64·65·66을 금융업으로 봅니다.
  - 다만 **64992(지주회사)에는 SK·LG와 KB금융·신한지주가 함께 들어 있어** 코드만으로 구분할 수 없었습니다. 그래서 64992는 회사명에 '금융'이 있을 때만 금융업으로 봅니다.

### 겪은 문제와 해결
- **무작위 25개사 점검 결과**
  - 보고서가 없는 8곳 중 7곳은 기업개황상 corp_cls=E(상장폐지 등)였습니다. 2단계에서 발견한 문제와 같습니다. → 화면에서 E이면 경고를 띄울 예정입니다.
  - 노루홀딩스는 재고자산을 `ifrs-full_InventoriesTotal` 코드로 공시했습니다. → account_map.py에 코드를 추가해 해결했습니다. (설정 파일로 분리한 효과)
  - 별도로 대체된 회사는 '지배기업 소유주지분' 계정이 없습니다. 별도재무제표에는 비지배지분 개념이 없기 때문입니다. → ROE를 당기순이익 ÷ 자본총계로 계산합니다.
  - 씨앤씨인터내셔널은 연결재무제표인데도 지배기업 귀속 순이익이 표시되지 않았습니다. → 이 경우 당기순이익으로 대체하고 사유를 표시합니다(4단계).
- **큰 금액의 정밀도**: pandas가 빈 값이 섞인 열을 실수(float)로 바꾸는데, float는 약 9,000조 원까지 원 단위가 정확해서 국내 기업 규모에서는 문제가 없습니다.

## 4단계: 비율 계산 + 테스트 (2026-10-18)

### 한 일
- `src/calculations.py`: 16개 비율을 순수 함수로 작성. 숫자만 받아 `Ratio(value, note)`를 돌려줍니다.
- `src/ratios.py`
  - 비율 목록(이름·분류·단위)
  - 계정표를 비율표로 조립하는 기능
  - 연환산·연결 ROE·이자비용 대용치 규칙
- 테스트 40개를 추가해 총 77개가 모두 통과했습니다.
  - 각 비율의 정상값, 분모 0, 자본잠식, 데이터 없음 케이스
  - 조립 규칙(연환산, 연결/별도 ROE, 대용치)

### 내린 결정과 이유
- **계산과 조립을 분리**
  - `calculations.py`는 "공식"만 담고, `ratios.py`는 "어떤 계정을 넣을지"를 담습니다.
  - 공식은 숫자 몇 개로 바로 테스트할 수 있고, 계정 규칙이 바뀌어도 공식 코드는 그대로입니다.
- **공식은 docstring 첫 줄 하나로 관리**: 화면 툴팁은 `inspect.getdoc()`으로 docstring 첫 줄을 읽어 씁니다. 코드와 화면의 공식이 어긋날 수 없습니다.
- **분모가 0이거나 음수면 None + 사유**
  - 사유 예: "분모가 0", "자본잠식(자본총계 음수)", "당기순손실", "데이터 없음: 재고자산"
  - 자기자본비율은 분모가 자산총계라서, 자본잠식이면 음수 비율을 그대로 보여줍니다. 음수 값 자체가 잠식 정보이기 때문입니다.
- **성장률의 적자 처리**
  - 전기가 적자이면 증가율이 의미가 없어 None으로 두고 "흑자전환" 또는 "적자지속"을 표시합니다.
  - 당기만 적자이면 값과 함께 "적자전환"을 표시합니다.
- **재고자산회전율은 매출액 기준**: 성격별 손익계산서를 쓰는 회사는 매출원가가 없어서, 한국은행 기업경영분석과 같은 기준으로 통일했습니다.
- **연환산 범위**
  - ROE·ROA·회전율처럼 '손익 ÷ 잔액' 형태인 비율만 연환산합니다.
  - 이익률·성장률·영업현금흐름/순이익은 같은 기간끼리 나누므로 연환산하지 않습니다.
- **이자보상배율의 대용치 사용(사용자 승인)**: 이자비용이 없으면 '이자의 지급'(현금기준)을 쓰고 비고에 표시합니다.
- **분기 총자산증가율은 '전기말 대비'**: 분기 재무상태표의 비교값이 전년 같은 분기말이 아니라 전기말이라서 비고에 표시합니다.

### 검증
삼성전자 2025 사업보고서(연결)로 직접 손으로 계산해 맞춰봤습니다.
- 영업이익률: 43.6조 ÷ 333.6조 = **13.07%** ✓
- ROE: 지배기업 귀속 순이익 44.26조 ÷ 평균 지배지분 408.0조 = **10.85%** ✓
- 부채비율: 부채 130.6조 ÷ 자본 436.3조 = **29.94%** ✓

7단계에서 사업보고서·외부 자료와 체계적으로 대조할 예정입니다.

  - 요약 카드 6개

- `.streamlit/config.toml`: 사용 통계 전송을 껐습니다.

### 내린 결정과 이유
- **검색은 입력창 + 결과 선택 상자 2단계로 구성**: Streamlit 기본 선택 상자의 자체 필터 대신, 2단계에서 만든 검색 함수(정확히 일치 우선, 종목코드 검색)를 그대로 쓰기 위해서입니다.
- **탭을 4개에서 5개로**: '영업현금흐름/순이익'을 둘 곳이 없어 '현금흐름' 탭을 추가했습니다.
- **툴팁 = docstring 첫 줄**: 카드의 ⓘ와 차트 제목의 ⓘ에 계산 함수의 공식을 그대로 보여줍니다.
- **요약 카드 증감은 %p로 표시**: 비율끼리의 차이라서 % 대신 퍼센트포인트를 씁니다. 부채비율은 낮을수록 좋으므로 증감 색을 반대로 했습니다.
- **차트**
  - 선 1개, 두께 2px, 점 8px
  - 마지막 값에만 숫자를 표시하고, 나머지는 마우스를 올리면 값과 비고가 보입니다.
  - 색은 색각이상 검증을 통과한 팔레트의 1번(파랑)을 씁니다. 6단계 비교에서는 1~3번을 씁니다.

### 겪은 문제와 해결
- **차트의 x축이 한 점으로 뭉쳐 보임**

  - 해결: 별도 라벨 대신 선 자체의 text 속성으로 마지막 점에만 라벨을 달았습니다.

- **성장률 사유가 "데이터 없음: 당기, 전기"로 불명확** → "당기 매출액, 전기 매출액"처럼 계정 이름이 나오도록 고쳤습니다.

## 7단계: 검증 (2026-10-18)

### 한 일
- `scripts/verify_reports.py`: 앱의 계산을 OpenDART의 **다른 두 API**와 자동으로 대조합니다.
  - 계정 금액: 주요계정 API(`fnlttSinglAcnt`)
  - 재무비율: 금융감독원이 계산해 주는 주요 재무지표 API(`fnlttSinglIndx`)
- 삼성전자·SK하이닉스·현대자동차의 2025 사업보고서, 삼성전자·현대자동차의 2026 반기보고서를 대조했습니다.
- DART 지표가 없는 6개 비율은 손계산으로 확인했습니다.
- 결과와 원인 분석은 `docs/verification.md`에, 자동 생성 표는 `docs/verification_result*.md`에 있습니다.

### 결과
- **계정 금액: 대조한 항목 모두 일치**
  - 사업보고서 16개 × 3개사
  - 반기보고서 19개 × 2개사 (3개월값 포함)
- **비율: 차이 난 것은 ROE와 분기 회전율뿐이고, 둘 다 앱의 의도적 기준 차이**
  - ROE: 앱은 지배기업 귀속 기준, DART는 전체(비지배지분 포함) 기준
  - 분기: 앱은 연환산, DART는 연환산하지 않음

### 내린 결정과 이유
- **'정답'으로 같은 API를 쓰지 않음**: 같은 데이터로 다시 계산하면 늘 일치해서 검증이 되지 않습니다. 그래서 별도 API, 특히 금감원이 직접 계산한 지표를 기준으로 삼았습니다.
- **원인을 '추정'이 아니라 '재현'으로 확정**: ROE 차이는 스크립트가 앱 데이터로 'DART 방식 ROE'를 직접 계산해 DART 값과 같아지는지 확인했습니다. 회전율 차이는 연환산 배수로 나눠 같아지는지 확인했습니다.
- DART 지표의 회전율이 ×100 단위(예: 61.695 = 0.617회)인 것을 발견해 맞춰 비교했습니다.

### 겪은 문제와 해결
- **반기 손익 6건이 처음엔 불일치로 나옴** → 앱이 아니라 검증 스크립트 쪽 문제였습니다.
  - 주요계정 API도 분기 `thstrm_amount`는 3개월치이고 누적은 `thstrm_add_amount`에 있는데, 스크립트가 3개월치와 비교하고 있었습니다.
  - 누적은 누적끼리, 3개월은 3개월끼리 비교하도록 고치자 모두 일치했습니다.
- **DART 지표에도 삼성전자 이자보상배율이 비어 있음** → 손익계산서에 이자비용이 없다는 3단계 발견과 일치하며, 대용치 결정을 뒷받침합니다.
