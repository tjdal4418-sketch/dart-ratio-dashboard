## 1. 프로젝트 지시 (2026-10-18)

```
# 프로젝트: DART 재무비율 분석 웹앱 (포트폴리오용)

## 배경
나는 회계사 시험 1차 합격자이고 세법·회계 지식은 있지만 개발은 초보다.
이 앱은 취업 포트폴리오용이며, 면접에서 코드와 계산 로직을 직접 설명할 수 있어야 한다.
그러니 코드는 단순하고 읽기 쉽게, 핵심 부분에는 한국어 주석을 달아줘.

## 목표
회사명을 검색하면 OpenDART API로 재무제표를 가져와
주요 재무비율을 계산하고 연도별 추이와 동종 기업 비교를 시각화하는 웹앱.

## 기술 스택
- Python 3.11+, Streamlit, pandas, requests, plotly, python-dotenv, pytest
- 배포 목표: Streamlit Community Cloud (무료)
- 더 나은 대안이 있다고 판단되면 코딩 전에 이유와 함께 제안만 하고 내 승인을 받아줘.

## OpenDART API 사용 규칙
1. 기업 고유번호: corpCode.xml(zip)을 내려받아 로컬에 캐시하고, 회사명 → corp_code 검색에 사용.
   상장사(stock_code가 있는 기업)만 검색 대상으로 필터링.
2. 재무제표: 단일회사 전체 재무제표 API(fnlttSinglAcntAll) 사용.
   - reprt_code: 11011(사업보고서), 11012(반기), 11013(1분기), 11014(3분기)
   - fs_div: CFS(연결) 우선, 없으면 OFS(별도)로 대체하고 화면에 어느 쪽인지 표시
3. 계정 매칭은 account_nm(계정명)이 아니라 account_id(IFRS 표준계정코드)를 우선 사용하고,
   account_id가 "-표준계정코드 미사용-"인 경우에만 계정명으로 대체 매칭.
   매칭 규칙은 별도 설정 파일(account_map.py 등)로 분리해 나중에 수정하기 쉽게.
4. 금액은 문자열(쉼표 포함)이므로 숫자로 변환. 빈 값/"-" 처리.
5. 손익계산서는 IS가 없고 CIS(포괄손익계산서)에만 있는 회사도 있으니 둘 다 탐색.
6. 분기보고서의 손익은 thstrm_amount(3개월)와 thstrm_add_amount(누적)가 다르므로 구분해서 처리.
7. API 응답 status 코드("000" 정상, "013" 데이터 없음, "020" 한도 초과 등)별 에러 처리.
8. 일일 호출 한도(20,000건)를 고려해 응답을 로컬 캐싱(st.cache_data 또는 파일 캐시).
9. API 키는 .env의 DART_API_KEY로 관리하고 절대 코드나 커밋에 포함하지 말 것.

## 계산할 재무비율 (calculations.py에 순수 함수로 분리)
- 안정성: 유동비율, 당좌비율((유동자산-재고자산)/유동부채), 부채비율, 자기자본비율, 이자보상배율(영업이익/이자비용)
- 수익성: 매출액영업이익률, 매출액순이익률, ROE, ROA
- 활동성: 총자산회전율, 매출채권회전율, 재고자산회전율
- 성장성: 매출액증가율, 영업이익증가율, 총자산증가율
- 현금흐름: 영업활동현금흐름 / 당기순이익
규칙:
- ROE·ROA·회전율은 (기초+기말)/2 평균 잔액 사용. 기초 잔액은 전기(frmtrm_amount) 값 사용.
- 연결 기준 ROE는 지배기업 소유주 귀속 순이익 / 지배기업 소유주지분으로 계산.
- 분모가 0이거나 음수(자본잠식 등)인 경우 None 반환 + 화면에 사유 표시.
- 각 비율의 공식을 코드 docstring과 화면 툴팁에 모두 표시.
- 은행·보험·증권 등 금융업은 재무제표 구조가 달라 일반 비율이 부적합하므로 경고 표시.

## 화면 구성
1. 사이드바: 회사 검색(자동완성), 기준연도, 보고서 종류, 연결/별도 선택
2. 요약 카드: 핵심 비율 4~6개 + 전년 대비 증감
3. 탭: 안정성 / 수익성 / 활동성 / 성장성 — 최근 3~5개년 추이 차트
4. 비교: 최대 3개 기업을 선택해 같은 비율 나란히 비교
5. 원본 데이터: 계산에 쓴 계정과 금액을 표로 보여주고 CSV 다운로드
6. 화면 하단에 데이터 출처(OpenDART)와 기준일 표시

## 품질 검증
- tests/에 pytest로 비율 계산 함수 단위 테스트 작성(정상값, 분모 0, 음수 자본 케이스).
- 삼성전자 등 2~3개 기업의 계산 결과를 실제 사업보고서 수치와 대조할 수 있도록
  검증용 스크립트를 만들고, 차이가 있으면 원인을 기록.

## Git / GitHub (포트폴리오용 — 매우 중요)
1. 시작 시 git init, .gitignore(.env, 캐시 폴더, __pycache__, corpCode 파일 등) 먼저 생성.
2. 아래 단계마다 작은 단위로 커밋하고, 커밋 메시지는 한국어로
   "feat: ...", "fix: ...", "docs: ...", "test: ..." 형식 사용.
3. docs/devlog.md에 단계별로 [날짜 / 한 일 / 내린 결정과 이유 / 겪은 문제와 해결]을 기록.
4. docs/prompts.md에 내가 입력한 프롬프트를 순서대로 기록(이 프롬프트 포함).
5. README.md: 프로젝트 소개, 주요 기능, 스크린샷 자리, 재무비율 공식 표, 실행 방법,
   기술 스택, 한계점과 향후 계획, AI(Claude Code) 활용 방식.
6. gh CLI가 로그인되어 있으면 공개 저장소를 만들어 push. 안 되어 있으면 방법을 안내하고 멈출 것.
   push 전에 .env가 커밋에 포함되지 않았는지 반드시 확인.

## 진행 방식
- 바로 코딩하지 말고 먼저 (1) 폴더 구조, (2) 단계별 개발 계획, (3) 불확실한 점이나 내게 확인할 질문을 제시하고 승인을 기다려.
- 승인 후 한 단계씩 진행하고, 각 단계가 끝나면 무엇을 했는지 짧게 요약 + 실행해서 확인하는 방법 + 커밋 결과를 알려줘.
- 단계 예시: 1) 환경 세팅·git 2) 기업코드 검색 3) 재무제표 수집·파싱 4) 비율 계산+테스트 5) 화면 6) 비교 기능 7) 검증 8) README·배포
```
